## Step 2. Versioned, adaptive instances

[INSTANCE-PLAN.md](INSTANCE-PLAN.md) defines the boundaries and acceptance scenarios and shows the `pi instance` workflow. Shared evidence for this step so far:

- `npm run check` passes, including formatting, dependency checks, entry-point budgets, install-lock validation, TypeScript, and browser import smoke.
- The complete coding-agent suite passed 3,027 tests in 330 files, with 54 tests skipped, using a dill-enabled interpreter. The opt-in native backend smoke was exercised separately below. The run includes instance, migration, native adapter, and real bundled child-delegation regressions.
- The Python runtime suite passed 47 tests through `uv run --no-project --python 3.11 --with pytest --with dill python -m pytest packages/coding-agent/python/tests -q`.
- The deterministic two-project scenario in `bench/rlm/instances/` succeeded with zero model calls (`/tmp/raga-instance-smoke-final/scenario.json`). It is a system smoke, not a learning-quality comparison.
- A real bubblewrap kernel confinement smoke passed on Linux.
- A real terminal run of an instance session started, rendered typed input, repainted after a resize from 110 to 80 columns, stayed in the same foreground process group, and exited with code 0 on Ctrl-D (`/tmp/raga-implementation/instance-tui.ansi`).
- Snapshot persistence passed with dill, including fork restoration into the fork's private directory without exposing the parent's snapshot mount.
- The package dry run includes all 196 bundled assets and both Python runtime source files, without generated Python caches.
- The documented `./pi-test.sh instance init` and `instance fork` commands created two distinct instances at the same accepted revision.

The real-model smoke demonstrates validated acquisition and explicit activation. It does not establish a held-out learning-quality gain. Automatic promotion remains disabled.

## Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-10-24 | The RLM runtime is native, not an extension. | See "Why the RLM runtime is native" in ARCHITECTURE.md. |
| 2026-10-24 | The kernel is a custom NDJSON process, not Jupyter. | No ZeroMQ or `ipykernel` dependency. Prime Agent runs the same design. |
| 2026-10-24 | Self-modification targets Python modules and harness state first. | Python reloads in a running session. TypeScript changes need a rebuild and a restart. |
| 2026-10-24 | Child sessions run in the host process for step 1. | One `ModelRuntime` and no daemon. A daemon can come later. |
| 2026-10-25 | The Node engine is not an agent-editable surface. | Supersedes the proposed guarded host self-patching path. Only harness artifacts can evolve, with trusted evaluation and promotion. |
| 2026-10-25 | Each instance owns a Git-versioned harness and separate mutable state. | Pin sessions and children to exact revisions; never fork credentials or live kernel state into a new instance. |
| 2026-10-25 | Memory promotion and retrieval are separate gates. | A retained lesson is not automatically relevant to every task or child. |
| 2026-10-25 | Portable pstack and no-mistakes ship with every new harness. | Move default engineering skills into M9a. Exclude Cursor-only workflows; pin dependencies and preserve licensing. No-mistakes repository enablement and publication require explicit authorization. |
| 2026-10-25 | Linux bubblewrap is the restricted execution backend. | M11 required one documented backend. Restricted execution fails closed on other platforms or when the probe fails. Learned-skill validation adds a seccomp filter. |
| 2026-10-25 | Child workspaces are plain checkouts without `.git`, managed by the supervisor's own Git metadata. | Workers cannot run Git against the project or install filters, merge drivers, or hooks. Integration validates combined changes in a separate checkout. |
| 2026-10-25 | Checkpoint refinement is an explicit, bounded command, not a scheduler. | Raga runs no scheduler process. The caller decides when to invoke it, and policy limits decide whether it runs. |
| 2026-10-25 | Promotion needs user approval unless an external held-out report supports policy promotion. | No held-out evidence exists yet. Changes to host extensions and settings always need the user. |
